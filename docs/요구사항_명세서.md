# TravelReady 요구사항 명세서

| 항목 | 내용 |
|---|---|
| 프로젝트명 | TravelReady (가칭) |
| 문서 버전 | 1.0 |
| 작성일 | 2026-11-08 |
| 문서 목적 | 이번 실습에서 구현할 기능과 동작 조건을 정의한다. |
| 문서 상태 | 초기 설계안. 세부 기준은 설계·구현 과정에서 구체화할 수 있다. |

## 1. 프로젝트 개요

### 1.1 목적

회원이 여행 계획을 등록하고 여행별 준비물을 관리할 수 있는 웹 사이트를 만든다. 여행 유형에 맞는 기본 준비물을 제공하여 사용자가 자신의 여행에 맞게 목록을 조정하고 준비 상태를 확인할 수 있도록 한다.

이번 프로젝트는 JSP, Servlet, JDBC를 이용해 MVC와 Front Controller 구조를 직접 적용하고 웹 요청이 처리되는 과정을 이해하는 것을 학습 목표로 한다.

### 1.2 이용 대상

- **비회원:** 회원가입과 로그인을 할 수 있는 방문자
- **회원:** 로그인 후 자신의 여행과 준비물을 관리하는 사용자

### 1.3 핵심 이용 흐름

회원가입 → 로그인 → 여행 등록 → 유형별 기본 준비물 생성 → 준비물 확인 및 관리 → 준비 상황 확인

## 2. 구현 범위

| 구분 | 포함 기능 |
|---|---|
| 회원 | 회원가입, 로그인, 로그아웃, 내 정보 조회 |
| 여행 | 등록, 목록 조회, 상세 조회, 수정, 삭제 |
| 체크리스트 | 여행 유형별 기본 준비물 생성, 목록 조회, 준비물 추가·삭제, 완료·완료 취소 |
| 진행 상황 | 여행별 완료한 준비물 수와 전체 준비물 수 표시 |

체크리스트는 여행 상세 화면에서 함께 확인하고 관리한다. 여행 유형은 **국내여행**과 **해외여행**으로 구분한다. 제주도나 일본과 같은 구체적인 장소는 여행지에 입력한다.

### 2.1 제외 범위

이번 실습에서는 다음을 구현 범위에 포함하지 않는다.

- 회원 정보 수정, 비밀번호 찾기, 회원 탈퇴
- 준비물 이름 수정, 정렬 및 카테고리 분류
- 관리자 화면, 여행 공유, 동행자 초대, 알림
- 쇼핑몰, 결제, AI 추천, 지도·날씨 API 등 외부 서비스 연동

## 3. 기능 요구사항

각 요구사항의 ID는 이후 기능 명세와 구현 내용을 연결할 때 사용한다. 아래 요구사항은 이번 실습의 기본 완성 범위에 해당한다.

### 3.1 회원

| ID | 요구사항명 | 요구사항 내용 |
|---|---|---|
| REQ-MEM-01 | 회원가입 | 비회원은 아이디, 비밀번호, 이름, 이메일을 입력하여 회원으로 가입할 수 있어야 한다. |
| REQ-MEM-02 | 아이디 중복 방지 | 이미 사용 중인 아이디로는 가입할 수 없어야 하며, 가입이 불가능한 이유를 안내해야 한다. |
| REQ-MEM-03 | 회원가입 입력 확인 | 필수 회원 정보가 누락된 경우 가입을 완료하지 않고 사용자에게 안내해야 한다. |
| REQ-MEM-04 | 로그인 | 회원은 아이디와 비밀번호가 일치하면 로그인할 수 있어야 한다. 일치하지 않으면 로그인하지 않고 안내해야 한다. |
| REQ-MEM-05 | 로그아웃 | 로그인한 회원은 로그아웃하여 로그인 상태를 종료할 수 있어야 한다. |
| REQ-MEM-06 | 내 정보 조회 | 로그인한 회원은 자신의 아이디, 이름, 이메일을 조회할 수 있어야 한다. 비밀번호는 화면에 표시하지 않는다. |

### 3.2 여행 관리

| ID | 요구사항명 | 요구사항 내용 |
|---|---|---|
| REQ-TRAVEL-01 | 여행 등록 | 로그인한 회원은 여행명, 여행지, 출발일, 도착일, 여행 유형을 입력하여 여행을 등록할 수 있어야 한다. |
| REQ-TRAVEL-02 | 필수 항목 확인 | 여행 등록 또는 수정 시 필수 항목이 빠져 있으면 저장하지 않고 사용자에게 안내해야 한다. |
| REQ-TRAVEL-03 | 여행 날짜 확인 | 여행의 도착일이 출발일보다 빠른 경우 저장하지 않고 사용자에게 안내해야 한다. 출발일과 도착일이 같은 여행은 등록할 수 있다. |
| REQ-TRAVEL-04 | 여행 목록 조회 | 로그인한 회원은 자신이 등록한 여행 목록을 조회할 수 있어야 한다. 등록한 여행이 없으면 이를 안내해야 한다. |
| REQ-TRAVEL-05 | 여행 상세 조회 | 로그인한 회원은 자신의 여행을 선택해 여행 정보와 해당 여행의 체크리스트를 조회할 수 있어야 한다. |
| REQ-TRAVEL-06 | 여행 수정 | 로그인한 회원은 자신의 여행명, 여행지, 출발일, 도착일, 여행 유형을 수정할 수 있어야 한다. |
| REQ-TRAVEL-07 | 여행 삭제 | 로그인한 회원은 자신의 여행을 삭제할 수 있어야 한다. 여행을 삭제하면 해당 여행에 속한 체크리스트도 함께 삭제되어야 한다. |
| REQ-TRAVEL-08 | 유형 수정 시 목록 유지 | 여행 유형을 수정하더라도 기존 체크리스트는 그대로 유지되어야 한다. |

### 3.3 체크리스트

| ID | 요구사항명 | 요구사항 내용 |
|---|---|---|
| REQ-CHECK-01 | 기본 준비물 생성 | 여행을 처음 등록할 때 선택한 여행 유형에 맞는 기본 준비물 목록이 해당 여행에 생성되어야 한다. |
| REQ-CHECK-02 | 체크리스트 조회 | 로그인한 회원은 자신의 여행 상세 화면에서 해당 여행의 준비물과 각 준비물의 완료 여부를 확인할 수 있어야 한다. |
| REQ-CHECK-03 | 준비물 추가 | 로그인한 회원은 자신의 여행에 준비물 이름을 입력하여 항목을 추가할 수 있어야 한다. 빈 이름은 저장하지 않고 안내해야 한다. |
| REQ-CHECK-04 | 준비물 삭제 | 로그인한 회원은 자신의 여행에 속한 준비물 항목을 삭제할 수 있어야 한다. 기본으로 생성된 항목도 삭제할 수 있다. |
| REQ-CHECK-05 | 준비 완료 | 로그인한 회원은 자신의 여행에 속한 준비물의 상태를 완료로 표시할 수 있어야 한다. |
| REQ-CHECK-06 | 준비 완료 취소 | 로그인한 회원은 완료한 준비물을 다시 미완료 상태로 변경할 수 있어야 한다. |
| REQ-CHECK-07 | 진행 상황 표시 | 회원은 여행 상세 화면에서 해당 여행의 완료한 준비물 수와 전체 준비물 수를 확인할 수 있어야 한다. 준비물이 없으면 `0 / 0`으로 표시한다. |

### 3.4 공통 및 접근 권한

| ID | 요구사항명 | 요구사항 내용 |
|---|---|---|
| REQ-COM-01 | 로그인 필요 | 여행 관리, 체크리스트 관리, 내 정보 조회는 로그인한 회원만 이용할 수 있어야 한다. 로그인하지 않은 사용자가 접근하면 로그인 화면으로 안내한다. |
| REQ-COM-02 | 본인 데이터 접근 | 회원은 자신의 여행과 그 여행의 체크리스트만 조회·변경·삭제할 수 있어야 한다. 다른 회원의 데이터에 접근하려는 요청은 처리하지 않아야 한다. |
| REQ-COM-03 | 오류 안내 | 입력 오류 또는 처리 실패 시 사용자에게 작업이 완료되지 않았음을 안내해야 한다. |
| REQ-COM-04 | 여행 등록의 일관성 | 여행 정보 저장과 기본 준비물 생성이 모두 성공한 경우에만 여행 등록이 완료되어야 한다. 중간에 실패하면 해당 여행 등록 결과가 남지 않아야 한다. |
| REQ-COM-05 | 저장 상태 유지 | 정상적으로 저장된 여행과 체크리스트 상태는 로그아웃 후 다시 로그인해도 확인할 수 있어야 한다. |

## 4. 기본 준비물 예시

여행 등록 시 해당 유형의 목록을 초기 준비물로 제공한다. 항목은 이후 설계 과정에서 조정할 수 있다. 생성된 항목의 초기 상태는 **미완료**이다.

| 유형 | 기본 준비물 예시 |
|---|---|
| 국내여행 | 신분증, 충전기, 보조배터리, 의류, 세면도구 |
| 해외여행 | 여권, 항공권 관련 준비, 환전, 여행자보험, 충전기, 어댑터 |

기본 준비물은 여행별 목록으로 만들어지므로, 한 여행에서 준비물을 삭제하거나 완료해도 다른 여행의 목록에는 영향을 주지 않는다.

## 5. 화면 구성 범위

| 화면 | 주요 내용 |
|---|---|
| 메인 | 서비스 시작 화면과 회원 기능으로 이동 |
| 회원가입 | 회원 정보 입력 및 가입 |
| 로그인 | 아이디와 비밀번호 입력 |
| 내 정보 | 로그인한 회원의 정보 조회 |
| 여행 목록 | 자신의 여행 목록 확인 및 등록 화면으로 이동 |
| 여행 등록 | 여행 정보 입력 및 등록 |
| 여행 상세 | 여행 정보, 체크리스트, 진행 상황 확인 및 관리 |
| 여행 수정 | 기존 여행 정보 변경 |

화면의 구체적인 배치, 파일명과 URL은 화면 및 기능 설계 단계에서 확정한다.

## 6. 기술 및 구조 제약

- Java, JSP, Servlet, JDBC를 기반으로 구현한다. Spring 프레임워크는 이번 범위에 포함하지 않는다.
- MVC 구조를 사용하고 화면, 요청 처리, 업무 처리, 데이터 접근의 역할을 구분한다.
- Front Controller 역할의 `DispatcherServlet`이 `.do` 요청을 받아 해당 Controller로 연결한다.
- 기본 요청 흐름은 `Client → DispatcherServlet → Controller → Service → DAO → DB`로 한다. 처리 결과는 JSP에 전달하여 출력한다.
- 회원, 여행, 체크리스트 데이터를 데이터베이스에 저장한다. 상세 테이블과 컬럼은 DB 설계에서 확정한다.

## 7. 구현 순서

- **1단계:** 회원가입·로그인 → 여행 등록·목록·상세 조회 → 기본 체크리스트 생성·조회. 여행 상세 화면에는 우선 여행 정보와 준비물 목록을 표시한다.
- **2단계:** 여행 수정·삭제 → 준비물 추가·삭제·완료·취소 → 진행 상황 표시

두 단계 모두 이번 프로젝트의 목표 범위이다. 1단계에서 전체 요청 흐름을 먼저 연결하고 2단계에서 관리 기능을 완성한다.

## 8. 추후 결정할 사항

기능 명세와 DB·화면 설계를 진행하면서 아래 세부 기준을 정한다.

- 회원 아이디·비밀번호·이름·이메일의 길이와 입력 형식, 비밀번호를 해시하여 저장하고 검증할 구체적인 방식
- 여행명·여행지·준비물 이름의 최대 길이와 준비물 이름 중복 허용 여부
- 여행 목록의 표시 순서와 오류 안내 문구
- 입력 오류 시 기존 입력값 유지 방법과 오류 항목 표시 방식, 성공 후 화면 이동 시 안내 메시지 전달 방식
- 여행 등록·삭제 시 여러 DB 작업을 일관되게 처리하기 위한 트랜잭션과 DB 연결 방식
- 화면별 상세 구성, URL, Controller, Service, DAO, VO 및 DB 구조
