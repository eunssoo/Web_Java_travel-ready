## 1. 문서 안내

요구사항 명세서가 **무엇을 제공해야 하는지** 정리한 문서라면, 이 문서는 그 요구사항을 만족하기 위해 **각 기능이 어떻게 동작하는지** 설명한다. 아래 URL, HTTP 방식과 클래스 이름은 구현을 돕기 위한 **설계안**이며, URL 및 클래스 상세 설계 때 확정한다.

기본 요청 흐름은 `Client → DispatcherServlet → Controller → Service → DAO → DB`이며, 조회 결과는 Controller가 JSP에 전달한다. 변경 작업이 성공하면 화면 이동 시 재요청으로 중복 저장되지 않도록 redirect를 사용한다.

### 1.1 공통 처리

- **로그인 확인:** 여행·체크리스트·내 정보 요청 시 서버에서 로그인 세션을 확인한다. 로그인하지 않았다면 로그인 화면으로 안내한다. 회원 ID는 입력값이 아니라 세션에서 가져온다. (REQ-COM-01)
- **소유권 확인:** 여행 번호나 체크리스트 번호를 전달받더라도 서버에서 해당 여행이 로그인한 회원의 소유인지 확인한다. 존재하지 않거나 권한이 없는 데이터는 처리하지 않고 안내한다. 체크리스트 항목은 해당 여행에 속하는지도 확인한다. (REQ-COM-02)
- **입력 및 오류 확인:** 화면과 서버에서 필요한 값을 검사한다. 서버 검사는 생략하지 않으며, 누락·잘못된 값·처리 실패 시 저장하지 않고 사용자에게 안내한다. (REQ-COM-03)
- **데이터 보관:** 정상 처리된 여행과 준비물은 DB에 저장하고 다시 로그인한 후에도 조회한다. (REQ-COM-05)
- **요청 방식:** 조회·입력 화면은 GET, 등록·수정·삭제·체크 변경 등 상태를 바꾸는 요청은 POST를 사용한다.
- **관련 구성:** 모든 `.do` 요청은 DispatcherServlet을 거쳐 각 Controller로 연결한다. 각 기능의 구성 요소는 예시이며 DB 세부 설계에 따라 조정할 수 있다.

## 3. 회원 기능

### FUNC-MEM-01. 회원가입

- **목적:** 비회원의 정보를 등록한다.
- **관련 요구사항:** REQ-MEM-01, 02, 03, REQ-COM-03
- **사전 조건:** 회원가입 화면에 접근한다.
- **입력:** 아이디, 비밀번호, 이름, 이메일
- **처리:**
  1. 필수 항목이 입력되었는지 서버에서 확인한다.
  2. 아이디 중복 여부를 확인한다.
  3. 조건을 만족하면 회원 정보를 DB에 저장한다. 비밀번호는 안전한 해시 방식으로 저장하도록 세부 방식을 정한다.
- **성공 결과:** 회원가입 완료를 안내하고 로그인 화면으로 이동한다.
- **예외:** 필수값 누락, 아이디 중복 또는 DB 저장 실패 시 가입하지 않고 원인에 맞는 메시지를 표시한다. 중복 여부는 실제 저장 시에도 보장한다.
- **관련 구성 예시:** MemberSignupController → MemberService → MemberDAO → MemberVO / 회원가입 JSP

### FUNC-MEM-02. 로그인

- **목적:** 등록된 회원인지 확인하고 로그인 상태를 만든다.
- **관련 요구사항:** REQ-MEM-04, REQ-COM-03
- **사전 조건:** 로그인 화면에 접근한다.
- **입력:** 아이디, 비밀번호
- **처리:** 필수 입력을 확인하고, 아이디로 회원을 조회한 다음 입력한 비밀번호가 저장된 해시와 일치하는지 해당 해시 방식의 검증 절차로 확인한다. 성공하면 서버 세션에 로그인 회원 정보를 저장한다.
- **성공 결과:** 여행 목록 화면으로 이동한다.
- **예외:** 입력이 누락되거나 아이디·비밀번호가 일치하지 않으면 로그인하지 않고 안내한다. 조회 실패 시 오류를 안내한다.
- **관련 구성 예시:** MemberLoginController → MemberService → MemberDAO → MemberVO / 로그인 JSP

### FUNC-MEM-03. 로그아웃

- **목적:** 현재 로그인 상태를 종료한다.
- **관련 요구사항:** REQ-MEM-05
- **사전 조건:** 로그인 상태
- **입력:** 로그아웃 요청
- **처리:** 로그인 세션을 종료한다.
- **성공 결과:** 메인 화면으로 이동한다. 이후 보호된 기능에 접근하면 로그인 화면으로 안내한다.
- **예외:** 이미 세션이 종료된 경우에도 메인 또는 로그인 화면으로 안내한다.
- **관련 구성 예시:** MemberLogoutController / 세션 처리

### FUNC-MEM-04. 내 정보 조회

- **목적:** 로그인한 회원의 정보를 확인한다.
- **관련 요구사항:** REQ-MEM-06, REQ-COM-01, 03
- **사전 조건:** 로그인 상태
- **입력:** 세션의 회원 ID
- **처리:** 로그인한 회원의 정보를 조회한다.
- **성공 결과:** 아이디, 이름, 이메일을 표시한다. 비밀번호는 표시하지 않는다.
- **예외:** 회원 정보를 조회할 수 없으면 오류를 안내한다. 비로그인 시 공통 처리에 따른다.
- **관련 구성 예시:** MemberInfoController → MemberService → MemberDAO → MemberVO / 내 정보 JSP

## 4. 여행 기능

### FUNC-TRAVEL-01. 여행 등록 및 기본 준비물 생성

- **목적:** 여행을 등록하고 유형에 맞는 초기 체크리스트를 만든다.
- **관련 요구사항:** REQ-TRAVEL-01, 02, 03, REQ-CHECK-01, REQ-COM-01, 03, 04, 05
- **사전 조건:** 로그인 상태
- **입력:** 여행명, 여행지, 출발일, 도착일, 여행 유형(국내·해외). 회원 ID는 세션에서 가져온다.
- **처리:**
  1. 필수 항목, 날짜 형식과 여행 유형을 확인한다. 도착일이 출발일보다 빠르면 저장하지 않는다. 같은 날은 허용한다.
  2. 로그인 회원에게 여행을 연결하여 저장한다.
  3. 선택한 유형의 기본 준비물을 해당 여행에 각각 미완료 상태로 생성한다.
  4. 여행 저장과 기본 준비물 생성이 모두 성공하면 등록을 완료한다. 중간에 실패하면 전체 작업을 취소한다.
- **성공 결과:** 생성한 여행의 상세 화면으로 이동해 여행 정보와 체크리스트를 표시한다.
- **예외:** 입력 오류 또는 저장 실패 시 등록하지 않고 등록 화면에서 오류를 안내한다.
- **관련 구성 예시:** TravelWriteController → TravelService → TravelDAO, ChecklistDAO → TravelVO, ChecklistVO / 여행 등록 JSP. 저장 작업의 일관성은 JDBC 트랜잭션으로 처리한다. 하나의 트랜잭션에 속한 DAO 작업은 같은 DB 연결을 사용하며, 연결을 전달하는 구체적인 방법은 상세 설계에서 정한다.

### FUNC-TRAVEL-02. 여행 목록 조회

- **목적:** 회원이 등록한 여행을 확인한다.
- **관련 요구사항:** REQ-TRAVEL-04, REQ-COM-01, 02, 03, 05
- **사전 조건:** 로그인 상태
- **입력:** 세션의 회원 ID
- **처리:** 해당 회원에게 속한 여행 목록을 조회한다.
- **성공 결과:** 여행명, 여행지, 날짜, 여행 유형을 목록에 표시하고 상세 조회와 등록 화면으로 이동할 수 있게 한다. 목록이 비어 있으면 등록된 여행이 없음을 안내한다.
- **예외:** 조회 실패 시 오류를 안내한다.
- **관련 구성 예시:** TravelListController → TravelService → TravelDAO → TravelVO / 여행 목록 JSP

### FUNC-TRAVEL-03. 여행 상세·체크리스트 조회

- **목적:** 여행 정보, 해당 여행의 준비물 및 진행 상황을 확인한다.
- **관련 요구사항:** REQ-TRAVEL-05, REQ-CHECK-02, 07, REQ-COM-01, 02, 03, 05
- **사전 조건:** 로그인 상태, 본인의 여행
- **입력:** 여행 번호, 세션의 회원 ID
- **처리:** 소유권을 확인하고 여행 정보와 해당 여행의 준비물 목록을 조회한다. 전체 항목 수와 완료 항목 수를 계산한다.
- **성공 결과:** 여행 정보, 준비물 이름과 완료 상태, `완료 수 / 전체 수`를 표시한다. 항목이 없으면 `0 / 0`과 빈 목록을 표시한다. 준비물 관리와 여행 수정·삭제 기능을 제공한다.
- **예외:** 여행이 없거나 본인 소유가 아니면 정보를 표시하지 않고 안내한다. 조회 실패 시 오류를 안내한다.
- **구현 순서:** 1단계에서는 여행 정보와 기본 준비물 목록을 표시하고, 2단계에서 완료 수와 전체 수 표시를 추가한다.
- **관련 구성 예시:** TravelDetailController → TravelService, ChecklistService → TravelDAO, ChecklistDAO → TravelVO, ChecklistVO / 여행 상세 JSP

### FUNC-TRAVEL-04. 여행 수정

- **목적:** 등록한 여행 정보를 변경한다.
- **관련 요구사항:** REQ-TRAVEL-02, 03, 06, 08, REQ-COM-01, 02, 03, 05
- **사전 조건:** 로그인 상태, 본인의 여행
- **입력:** 여행 번호, 여행명, 여행지, 출발일, 도착일, 여행 유형. 회원 ID는 세션에서 가져온다.
- **처리:** 수정 화면을 열 때와 저장 요청 시 각각 소유권을 확인한다. 필수 항목과 날짜, 유형을 검사한다. 도착일이 출발일보다 빠르면 저장하지 않으며, 같은 날짜는 허용한다. 조건이 맞으면 여행 정보를 저장한다. 유형이 바뀌어도 기존 체크리스트는 유지한다.
- **성공 결과:** 수정된 여행 상세 화면으로 이동한다.
- **예외:** 입력 오류, 소유권 확인 실패 또는 저장 실패 시 수정하지 않고 안내한다.
- **관련 구성 예시:** TravelUpdateController → TravelService → TravelDAO → TravelVO / 여행 수정 JSP

### FUNC-TRAVEL-05. 여행 삭제

- **목적:** 여행과 그 여행에 속한 준비물을 삭제한다.
- **관련 요구사항:** REQ-TRAVEL-07, REQ-COM-01, 02, 03, 05
- **사전 조건:** 로그인 상태, 본인의 여행
- **입력:** 여행 번호, 세션의 회원 ID
- **처리:** 서버에서 소유권을 확인한 뒤 해당 여행과 체크리스트를 함께 삭제한다. 삭제가 중간에 실패하면 부분적으로만 삭제되지 않도록 처리한다.
- **성공 결과:** 여행 목록으로 이동하고 삭제한 여행을 표시하지 않는다.
- **예외:** 여행이 없거나 권한이 없으면 삭제하지 않고 안내한다. 삭제 실패 시 오류를 안내한다.
- **관련 구성 예시:** TravelDeleteController → TravelService → TravelDAO, ChecklistDAO / 여행 상세 JSP

## 5. 체크리스트 기능

체크리스트는 여행 상세 화면 안에서 관리한다. 준비물 작업 후에는 해당 여행 상세 화면에서 변경 결과와 진행 상황을 다시 확인한다.

### FUNC-CHECK-01. 준비물 추가

- **목적:** 여행에 필요한 준비물을 직접 추가한다.
- **관련 요구사항:** REQ-CHECK-03, REQ-COM-01, 02, 03, 05
- **사전 조건:** 로그인 상태, 본인의 여행
- **입력:** 여행 번호, 준비물 이름, 세션의 회원 ID
- **처리:** 여행 소유권을 확인하고 준비물 이름이 비어 있지 않은지 검사한 뒤 해당 여행에 미완료 상태로 저장한다.
- **성공 결과:** 여행 상세 화면에 새 준비물과 갱신된 진행 상황을 표시한다.
- **예외:** 빈 이름, 소유권 확인 실패 또는 저장 실패 시 추가하지 않고 안내한다.
- **관련 구성 예시:** ChecklistAddController → ChecklistService → ChecklistDAO → ChecklistVO / 여행 상세 JSP

### FUNC-CHECK-02. 준비물 삭제

- **목적:** 필요 없는 준비물을 목록에서 제거한다.
- **관련 요구사항:** REQ-CHECK-04, REQ-COM-01, 02, 03, 05
- **사전 조건:** 로그인 상태, 본인의 여행에 속한 항목
- **입력:** 여행 번호, 준비물 번호, 세션의 회원 ID
- **처리:** 여행 소유권과 준비물이 해당 여행에 속하는지 확인하고 항목을 삭제한다. 기본 준비물도 삭제할 수 있다.
- **성공 결과:** 여행 상세 화면에서 삭제 결과와 갱신된 진행 상황을 표시한다.
- **예외:** 항목이 없거나 권한이 없거나 삭제에 실패하면 삭제하지 않고 안내한다.
- **관련 구성 예시:** ChecklistDeleteController → ChecklistService → ChecklistDAO / 여행 상세 JSP

### FUNC-CHECK-03. 준비 완료·취소

- **목적:** 준비물의 완료 여부를 변경한다.
- **관련 요구사항:** REQ-CHECK-05, 06, REQ-COM-01, 02, 03, 05
- **사전 조건:** 로그인 상태, 본인의 여행에 속한 항목
- **입력:** 여행 번호, 준비물 번호, 변경할 상태(완료 또는 미완료), 세션의 회원 ID
- **처리:** 소유권과 항목의 여행 소속, 상태값을 확인한 후 요청한 상태를 저장한다. 완료 상태에서는 미완료로, 미완료 상태에서는 완료로 변경할 수 있다.
- **성공 결과:** 여행 상세 화면에 변경된 완료 상태와 진행 상황을 표시한다.
- **예외:** 유효하지 않은 상태값, 존재하지 않는 항목, 권한 문제 또는 저장 실패 시 변경하지 않고 안내한다.
- **관련 구성 예시:** ChecklistCheckController → ChecklistService → ChecklistDAO → ChecklistVO / 여행 상세 JSP

## 6. 검토 및 추후 확정 사항

- 회원 정보의 길이와 입력 형식, 비밀번호 저장·검증에 사용할 구체적인 해시 방식
- 여행명·여행지·준비물 이름의 최대 길이, 준비물 이름 중복 허용 여부
- 기본 준비물 최종 목록과 관리 방식, 여행 목록 정렬 기준
- 오류 메시지의 구체적인 문구, 입력 오류 시 기존 입력값 유지 및 오류 항목 표시 방식, 삭제 전 확인 화면·대화상자 적용 여부
- 성공 후 redirect로 이동할 때 안내 메시지를 전달하는 구체적인 방법
- URL과 JSP 경로, Controller·Service·DAO·VO 이름 및 메서드, DB 테이블과 연결 방식
- 여행 등록과 삭제에서 트랜잭션을 적용하는 방법, DAO 간 DB 연결 전달 방식 및 DB 제약조건 구현 방식

위 사항은 아직 확정되지 않았다. 요구사항과 함께 검토한 후 화면·DB·상세 설계에서 결정한다.
